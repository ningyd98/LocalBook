# ReadFlow 界面与图标设计

> 作者：本次界面改版（设计系统 + 搜索窗口 + 供应商面板 + app 图标 + DMG 打包）
> 相关命令：`bash scripts/package_dmg.sh`（图标 → 构建 → 注入图标并重签 → 验证 → 打 DMG → 挂载后复验）
> 界面渲染证据：`verification/ui-snapshots/*.png`（由 `--render-ui <dir>` 生成）

---

## 1. 为什么先做「能看见」

这个项目此前**从未看到过自己的界面**：`screencapture` 回来是纯黑，辅助功能 API 返回 `-25211 apiDisabled`，于是一切关于 UI 的说法都只是「派生字符串」的说法（C30 也一直把 A24–A26 记为未覆盖）。

`--render-ui <dir>` 补上了这一环：它用 `NSHostingView` 在**离屏**完成一次真实的 AppKit 布局与绘制，把每个界面写成 PNG。它不需要窗口、显示器或登录会话。

> **先试过 `ImageRenderer`，被否掉了**：它只画 SwiftUI 自己的图元，控件会渲染成「不支持」的占位（搜索框回来是一条黄色禁用条），`List`/`ScrollView` 里延迟布局的内容整块缺失 —— 第一版快照是一张空窗口。离屏 `NSHostingView` 才是真正渲染界面的那条路。

**它证明了什么 / 不证明什么**（免得又变成一次「把派生证据当验收」）：

| 证明 | 不证明 |
| --- | --- |
| 布局、层级、间距、字号、颜色、控件的实际排布 | 窗口边框/工具栏等系统外观、动画与过渡 |
| 各状态（有结果 / 无结果 / 未配置 / 警告）下的真实渲染 | 交互（点击、悬停、键盘焦点）的真实行为 |
| 固定尺寸、**浅色**外观下的结果 | 深色外观、不同窗口尺寸下的自适应 |

## 2. 设计系统（`ReadFlow/UI/DesignSystem.swift`）

此前每个界面各自发明 padding、圆角与字号，"次要元数据"在三个窗口里长得像三种东西。可复用的视觉决策集中到一处：

- **色板** `RFColor`：强调色取自 app 图标的靛蓝；三种内容类型各有色相（高亮=琥珀 / 笔记=蓝 / 阅读条目=青）；语义色（警告 / 危险 / 成功）。
- **度量** `RFMetric`：圆角、栏距 `14`、行距 `6`、**固定标签列 `132`**。
- **组件**：`RFBadge`（带色调的胶囊标签）、`RFStatusDot`、`RFCard`（分组卡片）、`RFEmptyState`（空状态）、`RFFieldRow`（固定标签列 + 控件 + 帮助/警告行）。
- **日期** `RFDate.humanised`：界面不该给人看 `2026-09-13T05:22:56Z`。**解析失败时原样返回**，绝不编造一个看起来合理的日期。

## 3. 各界面改了什么

**搜索窗口**（主界面，收益最大）
- 结果行：正文（13pt medium）→ 上下文（次级）→ 元数据行（类型色标 + 来源 + 人类可读日期），行距/内边距统一，**悬停高亮**，分隔线缩进到文字。
- 新增**结果计数条**：「2 条结果 · 本地检索，无需网络」—— 回答"它到底搜了吗"。
- 空状态分**两种**：「还没输入」与「没搜到」需要不同的下一步动作，所以是两个界面而不是一句两边都不贴切的文案。
- 搜索框变成真正的圆角控件（描边 + 底色 + 清除按钮）。

**AI 供应商面板**（原先最明显的排版缺陷）
- 原先用 `Form`，标签是**字段内的占位符**，`Endpoint（如 https://api.openai.com/v1）` 折成两行、把输入框挤变形。
- 现在：固定标签列 + 分组卡片；http 明文警告贴在对应字段下方；开关行带解释；所有契约文案（§6.3 徽标、C18 禁用原因、钥匙串说明、只请求 `/models` 的说明）**逐字保留**。

**app 图标**（`packaging/make_icon.py`，无需 Xcode）
- 概念：**琥珀色书签**（阅读）+ **三条流动的白色丝带**（flow）；只用三个形状，16px 下仍可辨。
- 技术：Pillow 绘制超椭圆（Apple 连续圆角）→ `sips` 生成 10 档 `iconset` → `iconutil` 打包 `.icns`。
- 第一版被当场否掉：粗折线有**发丝裂缝**（PIL 画粗折线的接缝伪影）、书签压在文字上、V 型缺口没画出来 → 改为**按中心线偏移生成多边形**的丝带，并把书签移到独立一列。

**打包**（`scripts/package_dmg.sh`）
- 图标注入 app 包（`Contents/Resources/AppIcon.icns` + `CFBundleIconFile`）后**必须重新签名** —— 改动已签名包会让 `codesign --verify` 失败。
- 产物：`dist-dmg/ReadFlow-ReadFlow.dmg`（app + `/Applications` 软链 + 卷图标）。
- **验证的是 DMG 里那一份**：`hdiutil verify` → 挂载 → `codesign --verify --deep --strict` → 在**挂载卷里的二进制**上跑行为矩阵（`--self-check-storage` + 10 个 `--self-test` 出口 + 未知场景守卫）→ 卸载。验证暂存副本却发布另一个文件，是"认证了没人收到的东西"的经典做法。

## 4. 回归：这次改版自己抓到的一个缺陷

`render-search-row`（28 条断言）在打包门禁上**失败**：它有一条断言要求「显示的日期 == 原始字符串」，而我刚把 `displayDate` 改成人类可读格式。修法不是放宽断言，而是**让它断言映射**：

```
date == RFDate.humanised(raw)      // 访问器必须走那个唯一实现，而不是第二份格式化
```

并补了 3 条对映射本身的直接检查（可解析的时间戳不得回显 `T`/`Z`；无法解析的值原样返回、不得编造；同一天读作「今天」）。→ `render-search-row` 现为 **31 条断言**。

**这正是打包门禁的价值**：改动显示层不会让任何行为自检变红，只有把整条流水线跑在**最终产物**上才会暴露。
